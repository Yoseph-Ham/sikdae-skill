# 식대 정산 대장 생성기 (Claude Skill)

영수증 사진을 폴더째 던지면 **Claude 가 영수증을 직접 읽고** 일 한도를 적용한
개인경비 정산 대장 엑셀을 만들어 주는 Claude Skill.

매달 영수증 수십 장을 손으로 엑셀에 옮겨 적고, 같은 날 두 건이면 한도 계산을 다시 하고,
규정이 바뀌면 어느 달치부터 새 한도인지 헷갈리는 — 그 반복 작업을 없애려고 만들었습니다.

```
영수증 폴더 (JPG/PNG/PDF/PPTX)
        │
        ▼
  prepare_receipts.py      폴더 스캔, PDF/PPTX → 이미지, 여백 크롭
        │
        ▼
   ★ Claude 직접 판독 ★     사용일자 / 상호 / 금액
        │                   (OCR 라이브러리 없음)
        ▼
   limit_policy.py         날짜 구간별 일 한도 결정 + 출처 추적
   expense_processor.py    일자별 합산 → 한도 적용 → 인정/초과 분리
        │
        ▼
   excel_writer.py         회사 양식 xlsx (내역 시트 + 영수증 이미지 시트)
```

## 빠른 시작

```bash
git clone https://github.com/Yoseph-Ham/sikdae-skill.git
```

이 폴더를 Claude 의 skills 디렉터리에 두거나 링크합니다.

```bash
# Windows (관리자 권한 불필요)
mklink /J "%USERPROFILE%\.claude\skills\sikdae-expense-report" "C:\경로\sikdae-skill"

# macOS / Linux
ln -s /경로/sikdae-skill ~/.claude/skills/sikdae-expense-report
```

> 링크(junction)로 걸어두면 레포를 고칠 때 스킬에 즉시 반영됩니다. 두 벌 관리할 필요가 없습니다.

의존성은 [`uv`](https://docs.astral.sh/uv/) 가 최초 실행 시 자동 설치합니다 (`pip install` 불필요).
**요구사항**: Python 3.11+, `uv`, 로컬 파일시스템 접근 권한

최초 1회 인적사항을 저장합니다 (이후 자동으로 쓰입니다):

```bash
uv run python scripts/manage_config.py save --name "홍길동" --position "매니저" --department "경영관리팀"
```

## 사용법

### 1. Claude 와 대화로 (주 사용 방식)

```
나: 이번 달 식대 정리해줘. 영수증은 D:\영수증\2026-07 에 있어
```

Claude 가 폴더를 스캔하고, 영수증을 한 장씩 읽고, 판독 결과를 표로 보여주며
확인을 받은 뒤 엑셀을 만듭니다. 애매한 영수증은 확정 전에 되물어봅니다.

한도를 이번만 다르게 하려면 그냥 말하면 됩니다:

```
나: 이번엔 한도 2만원으로 계산해줘
```

### 2. 명령줄로

```bash
# 폴더 스캔 → 매니페스트 (어떤 이미지를 읽어야 하는지 목록)
uv run python scripts/prepare_receipts.py "D:/영수증/2026-07" --output manifest.json

# 판독 결과 JSON 을 준비한 뒤 → 엑셀 생성
uv run python scripts/generate_excel.py receipts.json --output 정산서.xlsx
```

중간의 "판독"은 Claude 가 하는 일입니다. CLI 만으로 끝까지 가려면
아래 형식의 JSON 을 직접 작성해야 합니다:

```json
[
  {"date": "2026-07-02", "merchant": "행복분식", "amount": 18000, "image_path": "..."},
  {"date": null,         "merchant": "",         "amount": null,  "image_path": "..."}
]
```

> **읽지 못한 값은 반드시 `null`.** 오늘 날짜나 `0` 으로 채우면 '확인 필요' 분류가
> 무력화되어 틀린 정산서를 그대로 제출하게 됩니다.

## 한도 관리

일 한도는 **코드 어디에도 하드코딩되어 있지 않습니다.**
아래 우선순위로 결정되고, 실행할 때마다 **적용된 한도와 그 출처가 출력**됩니다.

| 순위 | 출처 | 지정 방법 | 적용 범위 |
|---|---|---|---|
| 1 | 대화 지시 | Claude 에게 "이번엔 2만원" | 그 회차만 |
| 2 | 실행 인자 | `--daily-limit 20000` | 그 회차만 |
| 3 | config 날짜 구간 | `config.json` 의 `history` | **영수증 사용일자별** |
| 4 | config 기본값 | `config.json` 의 `default` | 구간에 안 걸리는 날짜 |
| 5 | 내장 기본값 | (config.json 이 없을 때만) 15,000원 | 전체 |

### 상황별 대응표

| 상황 | 할 일 | 과거분 영향 |
|---|---|---|
| **회사 규정이 바뀌었다** (앞으로 계속) | `config.json` 의 `history` 에 **한 줄 추가** | 없음 — 과거는 옛 한도 유지 |
| **이번 정산만 다르게** | Claude 에게 말하거나 `--daily-limit` | 없음 — 파일 안 바뀜 |
| **과거에 잘못 넣은 값을 고쳐야** | 해당 `history` 항목의 `amount` 수정 | 그 구간 전체가 재계산됨 |
| **한도를 아예 안 쓰고 싶다** | 아주 큰 값 지정 (`--daily-limit 99999999`) | 없음 |

### 규정이 바뀌었을 때 (가장 흔한 경우)

예: **2026년 9월 1일부터 한도가 15,000원 → 20,000원으로 인상**

**1단계 — `config.json` 을 엽니다.** 현재 이렇게 되어 있습니다:

```json
{
  "daily_limit": {
    "default": 15000,
    "history": [
      { "from": "2025-01-01", "amount": 12000, "note": "2025년 규정" },
      { "from": "2026-06-01", "amount": 15000, "note": "2026-06 인상" }
    ]
  }
}
```

**2단계 — `history` 배열 **끝에 한 줄만 추가**합니다.** 기존 줄은 그대로 둡니다.

```json
{
  "daily_limit": {
    "default": 15000,
    "history": [
      { "from": "2025-01-01", "amount": 12000, "note": "2025년 규정" },
      { "from": "2026-06-01", "amount": 15000, "note": "2026-06 인상" },
      { "from": "2026-09-01", "amount": 20000, "note": "2026-09 인상" }
    ]
  }
}
```

앞 줄 끝에 **쉼표(`,`) 붙이는 것을 잊지 마세요.** JSON 은 쉼표 하나 빠지면 파일 전체를 못 읽습니다.

**3단계 — 저장.** 끝입니다. 코드 수정도, 재설치도, 재시작도 필요 없습니다.

**4단계 — 제대로 들어갔는지 확인합니다.**

```bash
uv run python scripts/manage_config.py show-limit --on 2026-08-31   # 옛 한도여야 함
uv run python scripts/manage_config.py show-limit --on 2026-09-01   # 새 한도여야 함
```

```
2026-08-31 적용 한도: 15,000원 (출처: config.json 구간 2026-06-01~ (2026-06 인상))
2026-09-01 적용 한도: 20,000원 (출처: config.json 구간 2026-09-01~ (2026-09 인상))
```

이렇게 나오면 성공입니다. 8월분을 뒤늦게 제출해도 15,000원으로,
9월분은 20,000원으로 각각 계산됩니다. **한 번의 실행에 두 달치가 섞여 있어도 각각 맞게 적용됩니다.**

### `from` 날짜는 "규정 시행일"입니다

공지받은 날이나 파일을 고치는 날이 아니라, **그 한도가 적용되기 시작하는 날**을 넣습니다.
해당 날짜 **당일부터** 새 한도이고, 다음 항목의 `from` 전날까지 유효합니다.

- 8월 20일에 "9월 1일부터 인상" 공지를 받았다 → `"from": "2026-09-01"`
- 소급 적용이라 "7월 1일부터 소급해서 올려준다" → `"from": "2026-07-01"` (7월분이 재계산됩니다)

### 이번 회차만 다르게

`config.json` 은 건드리지 않습니다.

```
나: 이번엔 한도 2만원으로 해줘
```
```bash
uv run python scripts/generate_excel.py receipts.json --daily-limit 20000
```

결과에 출처가 이렇게 찍힙니다:

```
========================================================
적용 한도: 20,000원
출처: 대화 지시
(config.json 의 날짜 구간 이력보다 우선 적용되었습니다)
========================================================
```

> 대화로 지시하면 출처가 `대화 지시`, 명령줄 인자면 `실행 인자` 로 구분되어 기록됩니다.
> 둘 다 주면 대화 지시가 이깁니다.

### ⚠ 흔한 실수

| 하지 말 것 | 왜 |
|---|---|
| 기존 `history` 항목을 **지우기** | 그 기간 과거 영수증이 엉뚱한 한도로 계산됩니다 |
| 기존 항목의 `amount` 를 **덮어쓰기** | 인상 이력이 사라지고 과거분이 소급 재계산됩니다 |
| `default` 만 고치고 끝내기 | `history` 구간에 걸리는 날짜는 `default` 를 보지 않습니다 |
| `from` 에 공지받은 날 넣기 | 시행일을 넣어야 합니다 |
| 앞 줄에 쉼표 안 붙이기 | JSON 파싱 실패 → 내장 기본값 15,000원으로 동작합니다 |

`config.json` 이 깨지면 조용히 넘어가지 않고 경고를 출력한 뒤 내장 기본값으로 동작합니다:

```
경고: .../config.json 를 읽지 못해 내장 기본값을 사용합니다 (Expecting ',' delimiter: line 8 column 5)
```

### 적용된 한도는 항상 기록됩니다

실행할 때마다 표준출력에 나오고, **생성된 엑셀 하단에도 남습니다.**
나중에 "이 대장 한도 얼마로 계산한 거냐"는 질문에 파일만 보고 답할 수 있습니다.

```
적용된 일 한도
적용 한도: 사용일자 구간에 따라 다름
  - 2026-05-28 ~ 2026-05-28: 12,000원  (출처: config.json 구간 2025-01-01~ (2025년 규정))
  - 2026-07-02 ~ 2026-07-06: 20,000원  (출처: config.json 구간 2026-07-01~ (2026-07 재인상))
```

> **JSON 을 쓰는 이유**: 외부 파서 의존성 없이 표준 라이브러리만으로 읽기 위해서입니다.
> 주석이 필요하면 `_comment` 필드를 쓰세요 (`samples/config.sample.json` 참고).

## 판정 규칙

- **같은 날 여러 건은 합산 후 한도까지만 인정**하고, 초과분은 `초과금액` 컬럼으로 분리합니다.
  원 결제금액은 절대 덮어쓰지 않습니다.
- **미사용 한도는 다음 날로 이월되지 않습니다.**
- 같은 날에는 **금액이 큰 건부터** 한도를 채웁니다.
- **날짜나 금액을 읽지 못한 영수증은 임의로 채우지 않습니다.** '확인 필요'로 분류해
  붉은색으로 표시하고 합계에서 제외합니다. 사람이 원본을 보고 직접 채워야 합니다.
  금액 칸은 `0` 이 아니라 **빈 칸**으로 둡니다 — `0` 은 "0원 결제"로 읽혀 오류를 놓치게 됩니다.
- 상호를 못 읽어도 날짜·금액이 있으면 **정산은 정확**하므로 합계에 포함하고 비고로만 표시합니다.

## 예시 출력

### 터미널

```
========================================================
적용 한도: 사용일자 구간에 따라 다름
  - 2026-05-28 ~ 2026-05-28: 12,000원  (출처: config.json 구간 2025-01-01~ (2025년 규정))
  - 2026-07-02 ~ 2026-07-06: 20,000원  (출처: config.json 구간 2026-07-01~ (2026-07 재인상))
========================================================
영수증 7건 처리
  결제금액 합계 : 77,500원
  인정금액 합계 : 63,000원   ← 실제 청구액
  초과금액 합계 : 14,500원
  확인 필요     : 1건 (한도 계산에서 제외됨)
      - (상호 미판독): 확인 필요: 사용일자 미판독, 금액 미판독 — 원본 영수증을 보고 직접 입력
```

### 엑셀 (Sheet 1)

| NO. | 사용날짜 | 사용처 | 항목 구분 | 사용내역 | 결제금액 | 인정금액 | 초과금액 | 참석자 | 비고 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | 26.05.28 | 옛날국밥 예시점 | 식대 | 점심식대 | 14,000 | 12,000 | 2,000 | 홍길동 | 한도 초과 2,000원 (일 한도 12,000원) |
| 2 | 26.07.02 | 행복분식 테스트점 | 식대 | 점심식대 | 18,000 | 18,000 | | 홍길동 | |
| 3 | 26.07.02 | 카페 하루 (가상) | 식대 | 점심식대 | 9,000 | 2,000 | 7,000 | 홍길동 | 한도 초과 7,000원 (일 한도 20,000원) |
| 4 | 26.07.03 | 미래식당 3호점 | 식대 | 점심식대 | 11,000 | 11,000 | | 홍길동 | |
| 5 | 26.07.06 | 면류연구소 (샘플) | 식대 | 점심식대 | 13,500 | 13,500 | | 홍길동 | |
| 6 | 26.07.06 | 그린샐러드 데모점 | 식대 | 점심식대 | 12,000 | 6,500 | 5,500 | 홍길동 | 한도 초과 5,500원 (일 한도 20,000원) |
| 7 | | (상호 미판독) | 식대 | 점심식대 | | | | 홍길동 | 🔴 확인 필요: 사용일자·금액 미판독 |
| | **합계** | | | | **77,500** | **63,000** | **14,500** | ← 인정금액이 실제 청구액 | |

- 2·3행이 같은 날(07-02) → 합산 27,000원, 한도 20,000원까지만 인정, 7,000원은 초과분
- 1행은 규정 변경 **이전** 날짜라 12,000원 한도 적용 (**소급 재계산 없음**)
- 7행은 붉은색 — 판독 실패 건, 합계 미포함
- 같은 날 복수 결제는 색상으로 그룹 표시

**Sheet 2 (영수증)**: 원본 영수증 이미지가 5열 그리드로 첨부됩니다.
카드사 PDF 전표는 A4 한가운데 영수증이 작게 박혀 있어 그대로 넣으면 셀 대부분이 흰 여백입니다.
변환 단계에서 여백을 자동으로 잘라내(실측: 면적 100% → 26%) 알아볼 수 있는 크기로 넣습니다.
다크모드 영수증도 동일하게 처리됩니다.

## 문제 해결

| 증상 | 원인 / 해결 |
|---|---|
| `경고: config.json 를 읽지 못해...` | JSON 문법 오류. 대개 쉼표 누락. 내장 기본값 15,000원으로 동작 중 |
| 한도를 바꿨는데 안 먹음 | `--daily-limit` 이나 대화 지시가 우선 적용된 것. 출력의 `출처:` 줄 확인 |
| 과거분이 새 한도로 계산됨 | 기존 `history` 항목을 수정·삭제했는지 확인. 추가만 해야 함 |
| `ERROR: 제출자 성명이 없습니다` | `manage_config.py save` 를 먼저 실행하거나 `--name` 으로 전달 |
| `ERROR: 엑셀 저장 실패` | 같은 이름의 파일이 Excel 에서 열려 있는지 확인 |
| `0건 발견` | 폴더 경로 확인. 지원 형식은 JPG/PNG/BMP/TIFF/PDF/PPTX |
| 영수증이 깨알만하게 들어감 | 여백 크롭이 실패한 경우. 이미지를 직접 잘라서 다시 넣어보세요 |

### 왜 OCR 을 걷어냈나

이전 버전은 EasyOCR 기반 데스크톱 앱이었습니다. 잘 되는 영수증은 잘 됐지만:

| 문제 | OCR 버전 | 현재 (Claude 판독) |
|---|---|---|
| 다크모드 영수증 | 이미지 반전 전처리 필요, 그래도 인식률 낮음 | 그냥 읽음 |
| 간편결제 스크린샷 | 광고 배너를 상호로 오인 → 예외 패턴 사전 관리 | 문맥으로 구분 |
| 상호명 오타 | 보정 사전 28개를 손으로 유지보수 | 불필요 |
| 부가세 vs 합계 | 키워드 우선순위 규칙으로 분기 | 영수증 구조를 보고 판단 |
| 배포 크기 | ~773MB (PyTorch 포함) | 스크립트 몇 개 |

판독 규칙은 코드가 아니라 [`SKILL.md`](SKILL.md) 에 자연어로 적혀 있어서,
새 영수증 형식이 나와도 사전이나 정규식이 아니라 문장 한 줄을 고치면 됩니다.

반대로 **한도 판정과 엑셀 생성은 Python 에 남겼습니다.** 돈 계산은 매번 똑같은 결과가
나와야 하고, 테스트로 고정할 수 있어야 하기 때문입니다.

## 개인정보 취급

이 레포는 공개를 전제로 만들어졌습니다.

- **실제 영수증·정산서·직원 실명은 커밋되지 않습니다.** `.gitignore` 가 입력/출력 폴더 전체와
  모든 이미지·문서·엑셀 확장자를 차단합니다.
- `samples/` 예외는 확장자를 명시했습니다 — 실제 영수증을 `samples/` 안에 둬도 커밋되지 않습니다.
- 제출자 인적사항은 레포가 아니라 `~/.sikdae_config.json` 에 저장됩니다 (역시 gitignore 대상).
- `samples/` 의 상호·금액·카드번호·사업자번호·인명은 **전부 지어낸 것**이며 실존 대상과 무관합니다.

### 배포할 때 주의

`.gitignore` 는 **커밋만** 막습니다. 폴더를 통째로 zip 으로 묶으면 무시 대상 파일까지
그대로 딸려갑니다 — 생성해 둔 실제 정산서가 여기 해당합니다.
배포용 zip 은 추적 중인 파일만 묶으세요:

```bash
git archive --format=zip -o sikdae-skill.zip HEAD
```
